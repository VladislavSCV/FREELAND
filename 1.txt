# Техническое Задание (ТЗ): Модернизация MVP Freelance OS до автономного автопилота

**Цель проекта**: Перевести существующий MVP Freelance OS (FastAPI + PostgreSQL + Docker Compose) из режима полуавтоматического контроля в полностью автономную систему мониторинга, оценки, авто-отклика и учета проектов с деплоем на Timeweb VPS.

---

### Архитектура изменений и модули для реализации

```
[ Источники: Биржи / TG-каналы ]
              │ (Bright Data Scraper Worker)
              ▼
[ FastAPI Backend / PostgreSQL ] ───&gt; [ Real LLM Evaluator ]
              │                               │
              │                      (Score &gt;= 8: Auto-apply)
              │                      (Score 5–7: TG Alert)
              ▼
[ Telegram Bot (aiogram / Webhook) ] &lt;───&gt; [ Пользователь (1-Click Управление) ]
              │
              └──&gt; [ Модуль Оплат: Ручной учет / Prodamus &amp; ЮKassa Webhooks ]

```

### Модуль 1\. Интеграция с Bright Data для фонового парсинга заказов

* **Задача**: Заменить демо-данные (seed) на фоновый асинхронный воркер сканирования заказов через прокси Bright Data [cite: 39, 40].
* **Реализация в коде**:
  1. Создать воркер `app/workers/scraper.py`, использующий `aiohttp` или `httpx` с прокси-авторизацией Bright Data (`BRIGHTDATA_TOKEN` / Proxy Credentials).
  2. Настроить периодический сбор (Cron/Interval каждые 5–10 минут) с публичных API/RSS фриланс-бирж (Kwork, FL.ru) и открытых Telegram-каналов с заказами [cite: 3, 39].
  3. Реализовать парсинг полей: `external_id`, `title`, `description`, `budget`, `url`, `source_platform`, `created_at`.
  4. Сохранять новые заказы в PostgreSQL со статусом `NEW`. Добавить проверку уникальности по `external_id` или хэшу текста для предотвращения дублей.

### Модуль 2\. Замена Mock-анализа на реальный LLM Evaluator

* **Задача**: Подключить реальный AI-анализ заявок через API (OpenAI / Claude / DeepSeek) [cite: 7, 30].
* **Реализация в коде**:
  1. В `app/services/ai_evaluator.py` заменить тестовую mock-логику на асинхронный API-клиент.
  2. Формат системного промпта:

&gt; *«Ты — AI-ассистент фрилансера с профилем [Указать стек: Python, Telegram API, AI-боты, n8n, CRM]. Проанализируй вакансию ниже. Дай ответ строго в JSON: {"score": &lt;1-10&gt;, "match\_reason": "&lt;1 предложение&gt;", "proposal": "&lt;продающий текст отклика на 2-3 абзаца с упором на решение проблемы&gt;"}.»* [cite: 7, 14, 230]

* Сохранять полученные данные (`score`, `match_reason`, `proposal_draft`) в таблицу `applications`.

### Модуль 3\. Гибридный Pipeline авто-откликов (Threshold Auto-Apply)

* **Задача**: Автоматизировать отправку откликов в зависимости от балла релевантности (Score).
* **Логика конвейера**:
  * **Score &gt;= 8 (Высокая релевантность)**: Система автоматически запускает отправку предложения через API/парсер соответствующей биржи [cite: 39] и меняет статус заявки на `SENT`.
  * **Score 5–7 (Сомнительно)**: Система генерирует уведомление в Telegram с кнопками быстрого решения: `[Отправить]`, `[Редактировать]`, `[Пропустить]`.
  * **Score &lt; 5 (Низкая релевантность)**: Автоматически переводит заявку в статус `ARCHIVED`.

### Модуль 4\. Настройка Telegram-бота на Webhook

* **Задача**: Перевести Telegram-бота с long polling на Webhook в FastAPI для мгновенного взаимодействия [cite: 23, 24, 30].
* **Реализация в коде**:
  1. Добавить эндпоинт `POST /api/v1/telegram/webhook` с валидацией токена `TELEGRAM_BOT_TOKEN` и проверки `ALLOWED_TELEGRAM_IDS` [cite: 34].
  2. При отправке карточки заказа (Score 5–7) выводить:
    * Текст заказа и бюджет [cite: 28].
    * Причину оценки от LLM (`match_reason`).
    * Сгенерированный отклик (`proposal_draft`).
    * Инлайн-клавиатуру c CallbackQuery: `approve_<app_id>, edit_<app_id>, reject_<app_id>.
    Добавить административные команды:
    /status — сводка по обработанным заказам и отправленным proposal за день.
    /autopilot on/off — переключатель тумблера полной авто-отправки.
    Модуль 5. Управление проектами и ручной/автоматический учет оплат
    Задача: Позволить принимать оплату вручную (согласно запросу), сохранив готовность к интеграции эвайринга [cite: 7, 16, 210].
    Реализация в коде:
    Ручной учет:
    Добавить в Telegram-бота команду /pay_project <project_id> <amount>.
    По этой команде менять статус проекта на PAID, фиксировать сумму в БД и запускать фоновый worker формирования итогового отчета/файлов для клиента.
    Подготовка под авто-эквайринг:
    Создать контроллеры /api/v1/webhooks/prodamus и /api/v1/webhooks/yookassa [cite: 15, 16, 250].
    Настроить парсинг входящих JSON-вебхуков про успешную оплату (payment.succeeded / SuccessfulPayment), чтобы при включении эквайринга статус проекта обновлялся автоматически без изменения архитектуры [cite: 15, 250].
    Модуль 6. Конфигурация .env и деплой на Timeweb Cloud VPS
    Задача: Подготовить проект к запуску в продакшн-среде Timeweb VPS в Docker Compose [cite: 34].
    Правки в .env.example:
    # App & DB Config
    PROJECT_NAME="Freelance OS Production"
    DATABASE_URL="postgresql+asyncpg://user:pass@db:5432/freelance_os"
    
    # External APIs
    BRIGHTDATA_TOKEN="your_brightdata_proxy_token_here"
    OPENAI_API_KEY="sk-..."
    LLM_MODEL="gpt-4o-mini"
    
    # Telegram Config
    TELEGRAM_BOT_TOKEN="123456789:ABC..."
    ALLOWED_TELEGRAM_IDS="12345678,98765432"
    WEBHOOK_DOMAIN="https://your-timeweb-domain.ru"
    
    # Payment Config
    MANUAL_PAYMENT_MODE=true
    PRODAMUS_SECRET_KEY=""
    YOOKASSA_SHOP_ID=""
    Правки в docker-compose.yml:
    Для сервисов api, db и worker добавить политику restart: always.
    Добавить контейнер nginx в качестве Reverse Proxy (порт 80/443) с сертификатом Let's Encrypt для обеспечения HTTPS (обязательно для вебхуков Telegram и платежных систем) [cite: 24, 34].
